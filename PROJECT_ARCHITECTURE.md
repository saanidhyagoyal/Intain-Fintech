# Intain Loan Data Verification Copilot - System Architecture

## 1. Executive Summary
The Loan Data Verification Copilot is an enterprise-grade FinTech platform built to solve the complex problem of unstructured, messy, and conflicting loan data. It ingests legacy CSV files, flags data quality anomalies using a deterministic Validation Engine, leverages Generative AI to suggest automated patches, and records every state change on an immutable, cryptographically hashed event ledger. 

## 2. High-Level Data Flow
1. **Ingestion (Upload):** A user (Data Operator) uploads `loan_tape.csv` and/or `servicer_update.csv`. The backend parses the CSVs, enforcing critical data formatting.
2. **Deterministic Validation:** The `ValidationEngine` checks for missing IDs, negative balances, temporal paradoxes (maturity < origination), and cross-references existing records.
3. **Event Logging (The Ledger):** Valid rows are appended to the PostgreSQL/SQLite database as `LOAN_IMPORTED` events. Invalid fields spawn `ExceptionRecord` entries in the `OPEN` state.
4. **AI Patch Suggestion:** In the Reviewer Dashboard, an AI model (Gemini/Anthropic) evaluates the exception and the row context to suggest a JSON-formatted fix and assigns a confidence score.
5. **Human Approval & Appending:** A Data Reviewer accepts the AI patch or manually resolves the issue. This triggers an `AI_SUGGESTION_APPLIED` or `HUMAN_EDIT_APPLIED` event.
6. **Self-Healing Pipeline:** A background job monitors human edits. If a human consistently overrides a rule in a specific pattern, the AI synthesizes a new `ValidationRule`, essentially teaching the system to heal future data automatically.
7. **Canonical Record (Verified Vault):** Once all exceptions for a loan are resolved, a `LOAN_VERIFIED` event is stamped. The data is now considered immutable and trustworthy for structured finance workflows.

## 3. The Immutable Ledger (Event Sourcing)
Traditional databases rely on `UPDATE` statements, which destroy historical context. The Copilot strictly uses **Event Sourcing**.
*   **Append-Only:** No loan data is ever updated or deleted. Every change is an `INSERT` into the `loan_events` table (e.g., `LOAN_IMPORTED`, `HUMAN_EDIT_APPLIED`).
*   **State Projection:** To view a loan's current state, the backend uses `project_loan_state()`, a deterministic function that fetches the initial payload and sequentially applies all delta payloads (`event.payload`) in chronological order.
*   **Cryptographic Hashing:** Each event contains an `event_hash` generated by hashing the previous event's hash combined with the current payload (a micro-blockchain), ensuring tamper-evident history.
*   **Time Travel:** The `/api/audit/rewind` endpoint simply runs `project_loan_state()` but stops at a specific timestamp, allowing the UI's Audit Timeline scrubber to "rewind" the financial data precisely.

## 4. Self-Healing Pipeline Mechanics
1. **Trigger:** The system detects 3 or more identical `HUMAN_EDIT_APPLIED` events that correct a specific validation failure.
2. **Analysis:** The `ai_assistant.py` is invoked with the pattern of the human corrections.
3. **Synthesis:** The LLM generates a JSON representation of a new `ValidationRule` (e.g., conditional transformations for specific servicer formatting quirks).
4. **Activation:** The rule is saved to the database. Future ingestions are run through this new rule, turning former exceptions into auto-resolved events.

## 5. Complete File Tree Map

### Root Directory
*   `.env`: Centralized configuration, API keys, and mock user credentials.
*   `CHANGES.md`: Detailed changelog of system refactors and bug fixes.
*   `PROJECT_ARCHITECTURE.md`: High-level system design, event sourcing logic, and file tree.
*   `BACKEND_DOCS.md`: Technical documentation of the FastAPI engine, database, and API contracts.
*   `FRONTEND_DOCS.md`: Technical documentation of the React/Vite UI, Tailwind design system, and state.

### Backend (`/backend`)
*   `main.py`: FastAPI application entry point, mounts routers, handles CORS, and seeds default users.
*   `requirements.txt`: Python package dependencies (FastAPI, SQLAlchemy, Uvicorn, etc.).
*   `/app`
    *   `__init__.py`: Package initialization.
    *   `models.py`: SQLAlchemy ORM definitions (`User`, `LoanEvent`, `ExceptionRecord`, `ValidationRule`).
    *   `/core`
        *   `config.py`: Pydantic BaseSettings for environment variable management.
        *   `database.py`: SQLAlchemy engine setup and `SessionLocal` dependency.
        *   `security.py`: JWT token generation, verification, and `require_role` access control dependencies.
    *   `/api`
        *   `router.py`: Central router that aggregates all endpoints.
        *   `/endpoints`
            *   `auth.py`: Provides the `/login` endpoint to issue JWTs.
            *   `loans.py`: Endpoints for fetching projected loan states and individual loan details.
            *   `exceptions.py`: Endpoints for fetching, explaining, and resolving exceptions.
            *   `upload.py`: Ingestion endpoints for processing CSV files.
            *   `summary.py`: Aggregation endpoints for dashboard statistics.
            *   `ai.py`: Endpoints invoking LLMs for patch suggestions and rule generation.
            *   `audit.py`: Provides the `/rewind` endpoint for time-travel state projection.
    *   `/services`
        *   `validation_engine.py`: Deterministic business logic evaluating loan data integrity.
        *   `ai_assistant.py`: LangChain/OpenAI integrations providing sandboxed generative fixes.
        *   `ingestion.py`: CSV parsing logic, mapping rows to models, and triggering validations.
        *   `event_sourcing.py`: Core logic for appending events, calculating cryptographic hashes, and projecting state.

### Frontend (`/frontend`)
*   `package.json`: NPM dependencies (React, Vite, Tailwind, Lucide).
*   `tailwind.config.js`: Custom Intain branding configuration (colors, animations, fonts).
*   `index.html`: Vite entry point, imports Google Fonts (Plus Jakarta Sans, JetBrains Mono).
*   `/src`
    *   `main.tsx`: React DOM rendering entry point.
    *   `App.tsx`: React Router configuration mapping roles to dashboards.
    *   `index.css`: Global CSS containing the radial mesh background and `.glass-card` utilities.
    *   `/api`
        *   `client.ts`: Axios instance configured with an interceptor to attach JWTs.
    *   `/types`
        *   `index.ts`: TypeScript interfaces perfectly mirroring backend Pydantic schemas.
    *   `/components`
        *   `Sidebar.tsx`: Role-aware navigation menu.
        *   `Table.tsx`: Hyper-structured, right-aligned data table component for financial records.
        *   `UploadZone.tsx`: Drag-and-drop component for CSV ingestion.
        *   `StatsCard.tsx`: Metric display cards used across dashboards.
        *   `ExceptionCard.tsx`: Expandable card displaying failed validations and rendering the `AIPanel`.
        *   `AIPanel.tsx`: Custom AI component featuring confidence meters, generation metadata, and "Copilot Glow".
        *   `AuditTimeline.tsx`: Vertical event ledger with a premium video-style scrubber for time-travel.
    *   `/pages`
        *   `LoginPage.tsx`: Enterprise login screen with JWT authentication and environment-based Quick Logins.
        *   `AdminDash.tsx`: Unified tabbed view granting access to all modules for Master Admins.
        *   `OperatorDash.tsx`: Dashboard focused on ingestion statistics and recent uploads.
        *   `ReviewerDash.tsx`: Dashboard dedicated to resolving the exception queue.
        *   `ConsumerDash.tsx`: Dashboard displaying only cryptographically verified data.
        *   `LoanDetail.tsx`: Deep-dive view of a single loan, displaying its state, exceptions, and Audit Timeline.
